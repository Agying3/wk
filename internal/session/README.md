# 共享会话身份与粘性绑定

业务请求的会话入口统一为 `server.resolveSession`：在提示词随机替换和账号选择之前解析，结果放入请求上下文。Chat Completions、Responses、账号路由、提示词候选和公平队列使用同一个身份；功能模块不得自行从用户消息、提示词或 `user_id` 再推导会话键。

## 身份

`session.ExplicitIdentity` 按顺序读取 `metadata.conversation_id`、`conversation_id`、`conversation`、`prompt_cache_key`、`X-WorkBuddy-Session-ID`、`X-Session-ID`、`X-Conversation-ID`。字段位置变化而值相同时仍是同一会话。Responses 适配层先恢复 `previous_response_id` 的历史路由标识，再进入同一入口；没有标识的新 Responses 请求生成自己的根标识。

没有显式标识时，`PrefixDocument` 深复制截至首条 user 的开场，经过正常协议兼容转换但跳过随机重写，再由 `Resolver` 将规范化 system、tools、首条 user 及相关设置变成 HMAC 摘要。追加历史和采样参数不改变身份；相同开场可能合并，修改系统提示词、工具或首条 user 可能创建新会话，推荐客户端转发稳定 ID。没有 user 和显式 ID 时返回空身份，不建立跨请求绑定。

`Identity.Key` 按可信鉴权身份/分组隔离，与模型无关。`Identity.AccountKey(model)` 在同一身份上增加账号路由的模型范围。原始 ID 仅供旧账号迁移适配使用，不写入日志或绑定持久化；缓存前缀索引仍针对实际出站正文，不能反过来改写身份。

## 绑定核心

`BindingStore[V]` 统一管理互斥锁、滑动过期、容量、版本、按旧版本更新以及持久化失败回滚。新功能应复用 `Identity` 与此核心，提供值的选择逻辑、生命周期策略及存储适配，禁止另建独立的会话推断或绑定生命周期实现。

- 账号 `Router` 使用字符串 UID；沿用账号 TTL、冷条目淘汰、健康/权限校验、版本保护、Redis 异步镜像及加密交接。主账号满载时临时借用不改绑定；账号失效或模型冷却可迁移。
- 提示词使用规则 ID 到候选 ID 的映射；闲置 30 天过期、每小时至多续写一次、10000 项满额拒绝新绑定，加密保存到原提示词状态文件。账号迁移、模型变化和权重刷新不改变已有候选。
- `Update` / `UpdateAlias` 回调在锁内执行；修改映射或切片等引用值前必须复制。持久化回调不得重入同一绑定表；失败时目标、迁移别名、容量清理和版本一并恢复。

两个业务域可使用各自存储及过期策略，生命周期算法只维护这一份。诊断任务固定占用一个账号名额属于任务资源租约，结束时释放；它不推断或建立业务会话，也不消耗提示词业务绑定容量。

## 重叠升级的账号绑定

显式配置 `session.Config.Authority` 后，账号 Router 的读、分配、续期和 CAS 均同步访问同一 PostgreSQL 协调行。版本号跨进程单调递增；旧请求结束时携带的 Lease 不能改写新版已经迁移或重建的绑定。此模式跳过 Redis 异步镜像，协调不可用时不得使用本地表继续分配。发送上游前使用 `ResolveLeaseWithCandidatesChecked` 与 `ReplaceIfCurrentChecked`，把存储错误传给请求入口。

共享表只存 HMAC 会话摘要、UID、活跃时间及版本，所有版本必须保持相同会话盐和协调 domain。`InitializeShared` / `Import` 只在共享行首次创建时导入串行交接数据，候选版本不能拿旧交接快照覆盖正在更新的共享表。提示词绑定仍使用其各自存储和管理 owner 生命周期。

## 兼容

显式会话的账号键保持原格式。旧的推断账号绑定按旧出站前缀查找，并在当前权限与模型健康校验通过后沿用；提示词的旧键只读用于首次原子迁移，不再创建新旧键两份绑定。保留原会话盐或管理员凭证，确保重启后摘要稳定。

旧版无法识别迁移后的提示词键。需要回退时，同时恢复升级前的加密提示词状态备份；单纯回退二进制会丢失新格式绑定的命中。
